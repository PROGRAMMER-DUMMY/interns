# 05 — Phase P2: Delta + Databricks

## Goal

After P2:

- `design-medallion` emits both `*.duckdb.sql` AND `*.spark.py` for every table.
- `build-medallion --target delta` runs the pipeline on Databricks via the existing `JobsBackend` or `WarehouseBackend`.
- Compute failures under permissive mode trigger downsize-then-fallback with a loud `degraded_run: true` flag.
- Strict mode (`AUTORESEARCH_DATABRICKS_STRICT=1` or `cfg.databricks.fallback == "fail"`) halts on any compute failure.
- Each `build-medallion` run is an MLflow run tagged with the workspace, target, manifest_hash, run_id, and degraded_run flag.

## Prerequisites

- P0 + P1 shipped.
- Databricks integration is functional (per `MEMORY.md`: PRD `sessions/2026-05-11/databricks-integration`).
- `databricks-sdk`, `mlflow>=3.0`, `pyspark>=3.5.1`, optionally `databricks-connect` per the `databricks-full` extra in `pyproject.toml`.

## Requirements (must-haves)

1. **Delta/Spark emission**: every Bronze, Silver, Gold table gets a `.spark.py` sibling to its `.duckdb.sql`.
2. **MERGE-on-PK in Spark**: Silver Spark code uses `DeltaTable.merge(...).whenMatchedUpdateAll().whenNotMatchedInsertAll()`.
3. **Target selection at build time**: `--target {duckdb, delta, auto}`; auto reads `cfg.databricks.is_active()`.
4. **Strict mode honored**: `_strict_databricks(cfg)` from `core/execution/backend.py` is the only flag that gates fallback behavior.
5. **Downsize-then-fallback on permissive mode**: on compute failure, retry with smaller compute (lower wait timeout, smaller cluster spec, chunked partitions); if still failing, fall back to DuckDB and record `degraded_run: true`.
6. **MLflow integration**: every build is an MLflow run. Tags: workspace, target_declared, target_actual, manifest_hash, run_id, degraded_run. Metrics: per-layer row counts, assertion pass rates, total LLM USD. Artifacts: manifest.yaml, lineage.json, run.json.
7. **Unity Catalog schema naming**: when target is Delta, Bronze lives in `<ws>_medallion_bronze`, Silver in `<ws>_medallion_silver`, Gold in `<ws>_medallion_gold`. Workspace name normalized: lowercase, underscores instead of hyphens.

Do not hand-edit. Regenerate via `uv run design-medallion --target delta`.

from pyspark.sql import SparkSession
from pyspark.sql import functions as F

spark = SparkSession.builder.getOrCreate()

         .option("header", True)
         .option("inferSchema", True)
         .csv(SOURCE_PATH)
         .withColumn("_source_system", F.lit("hospital_a"))
         .withColumn("_source_file", F.lit(SOURCE_PATH))
         .withColumn("_load_ts", F.current_timestamp())
         .write
         .format("delta")
         .mode("append")  # watermarked-append in P2; full dedup logic in P3+
         .saveAsTable(TARGET)

**Silver (`silver/patient.spark.py`):**

```python
"""silver.patient — MERGE-on-PK from hospital_a + hospital_b."""
from pyspark.sql import SparkSession
from pyspark.sql import functions as F
from delta.tables import DeltaTable

spark = SparkSession.builder.getOrCreate()
TARGET = "hc_rcm_medallion_silver.patient"
SOURCES = [
    ("hc_rcm_medallion_bronze.patient__hospital_a", "hospital_a"),
    ("hc_rcm_medallion_bronze.patient__hospital_b", "hospital_b"),
]

source_df = None
for table, sys in SOURCES:
    df = spark.table(table).withColumn("source_system", F.lit(sys))
    source_df = df if source_df is None else source_df.unionByName(df, allowMissingColumns=True)

# Derived columns
source_df = source_df.withColumn(
    "age_at_service",
    F.floor(F.months_between(F.col("ServiceDate"), F.col("DOB")) / 12)
)
# PII hashing  (P3 wires the salt; placeholder here)
source_df = source_df.withColumn("patient_id_hash", F.sha2(F.col("patient_id").cast("string"), 256))

if not spark.catalog.tableExists(TARGET):
    source_df.limit(0).write.format("delta").saveAsTable(TARGET)

DeltaTable.forName(spark, TARGET).alias("tgt").merge(
    source_df.alias("src"),
    "tgt.source_system = src.source_system AND tgt.patient_id = src.patient_id",
).whenMatchedUpdateAll().whenNotMatchedInsertAll().execute()
```

### Downsize-then-fallback policy

```python
# core/medallion/databricks_target.py
from dataclasses import dataclass
from core.execution.backend import _strict_databricks, build_execution_backend

@dataclass
class CompromiseHistory:
    attempts: list[dict] = field(default_factory=list)
    degraded: bool = False
    fallback_reason: str = ""

def execute_with_downsize_then_fallback(task, time_budget, hard_timeout, log_path, cfg) -> tuple[ExecutionResult, CompromiseHistory]:
    history = CompromiseHistory()
    backend = build_execution_backend(cfg)
    primary = backend.execute(task, time_budget, hard_timeout, log_path)
    history.attempts.append({"target": cfg.databricks.execution, "exit_code": primary.exit_code})
    if primary.exit_code == 0:
        return primary, history

    if _strict_databricks(cfg):
        history.fallback_reason = "strict mode — no retry"
        return primary, history

    # Downsize retry: smaller compute, longer wait. Implementation-dependent on backend.
    downsized_task = {**task, "compute_hint": "small"}
    downsized = backend.execute(downsized_task, time_budget, hard_timeout * 2, log_path)
    history.attempts.append({"target": cfg.databricks.execution, "compute": "small", "exit_code": downsized.exit_code})
    if downsized.exit_code == 0:
        return downsized, history

    # DuckDB fallback
    from core.execution.backend import DuckDBBackend
    fallback = DuckDBBackend().execute(task, time_budget, hard_timeout, log_path)
    history.attempts.append({"target": "duckdb", "exit_code": fallback.exit_code})
    history.degraded = True
    history.fallback_reason = f"Databricks failed twice (exit codes {[a['exit_code'] for a in history.attempts[:-1]]})"
    return fallback, history
```

`run.json` records:

```json
"target_declared": "delta",
"target_actual": "duckdb",
"degraded_run": true,
"fallback_reason": "Databricks failed twice (exit codes [1, 1])",
"compromise_history": [
  {"target": "jobs",   "exit_code": 1},
  {"target": "jobs", "compute": "small", "exit_code": 1},
  {"target": "duckdb", "exit_code": 0}
]
```

### MLflow integration

```python
# core/medallion/mlflow_emit.py
import mlflow
from pathlib import Path

def start_run(workspace: str, manifest_hash: str, run_id: str, target_declared: str) -> str:
    mlflow.set_experiment(f"/medallion/{workspace}")
    run = mlflow.start_run(run_name=run_id, nested=False)
    mlflow.set_tags({
        "workspace": workspace,
        "target_declared": target_declared,
        "manifest_hash": manifest_hash,
        "run_id": run_id,
    })
    return run.info.run_id

def finalize_run(run_state: dict, run_state_dir: Path) -> None:
    mlflow.set_tag("target_actual", run_state["target_actual"])
    mlflow.set_tag("degraded_run", str(run_state["degraded_run"]))
    for table, status in run_state["per_table_status"].items():
        if "row_count_after" in status:
            mlflow.log_metric(f"rows.{table.replace('.', '_')}", status["row_count_after"])
        if "assertions" in status:
            passed = sum(1 for v in status["assertions"].values() if v == "pass")
            total = len(status["assertions"])
            mlflow.log_metric(f"assertions_pass_rate.{table.replace('.', '_')}", passed / max(total, 1))
    mlflow.log_artifact(str(run_state_dir / "run.json"))
    mlflow.log_artifact(str(run_state_dir.parent.parent.parent / "generated" / "medallion" / "manifest.yaml"))
    mlflow.log_artifact(str(run_state_dir.parent.parent.parent / "generated" / "medallion" / "lineage.json"))
    mlflow.end_run()
```

MLflow is optional — if the platform is running locally without `mlflow.set_tracking_uri` set, the run logs locally to `mlruns/`. The build orchestrator wraps `start_run`/`finalize_run` in try/except — MLflow unavailability never fails a build, only emits a warning.

## Implementation steps

### Step 1: extend `design-medallion` to emit Spark files

Add `_emit_bronze_sql_spark`, `_emit_silver_sql_spark`, `_emit_gold_sql_spark` in `design.py` (or move all emitters to a new `core/medallion/sql_emitters.py` once you have two targets).

The design pass emits BOTH targets regardless of `manifest.target`. The target field gates which set the build pass actually executes. Reason: emit cost is low; the user can switch targets without re-running design.

### Step 2: write the Spark MERGE generator

Pattern as in §"Silver (silver/patient.spark.py)" above. Bind workspace name → UC schema name via a single helper:

```python
def uc_schema_for(workspace: str, layer: str) -> str:
    return f"{workspace.lower().replace('-', '_')}_medallion_{layer}"
```

### Step 3: extend `build-medallion`

Add `--target` flag; the orchestrator passes `target` to the SQL/Py emitter selector. When target=delta, the execution path uses `JobsBackend` / `WarehouseBackend` (existing) via `build_execution_backend(cfg)`.

### Step 4: implement downsize-then-fallback

`databricks_target.py` as above. Wire it into the build loop so each Bronze/Silver/Gold table goes through it, not directly through the backend.

### Step 5: MLflow integration

Wire `start_run` at the top of the build, `finalize_run` at the end. Wrap in `try/except mlflow.exceptions.MlflowException` and log a warning on failure.

### Step 6: extend the validator

No new validator checks for P2; just confirm both `.duckdb.sql` and `.spark.py` exist when target ∈ {auto, delta}. Add this as a soft warning (not error) if only one is present.

### Acceptance criteria

1. `design-medallion` produces both `.duckdb.sql` and `.spark.py` for every table.
2. `build-medallion --target duckdb` still works exactly as in P1 (no regression).
3. `build-medallion --target delta` on a configured Databricks workspace completes end-to-end; produces UC tables under `<ws>_medallion_{bronze,silver,gold}`.
4. Deliberately misconfigured Databricks cluster under permissive mode produces a successful run with `degraded_run: true` and `target_actual: "duckdb"` in `run.json`.
5. Same misconfiguration under strict mode (`AUTORESEARCH_DATABRICKS_STRICT=1`) halts with `MEDALLION_BUILD_FAIL`.
6. MLflow UI shows the run with all expected tags; manifest.yaml and lineage.json appear as artifacts.

## Risks

| Risk | Mitigation |
|---|---|
| Spark/Delta dialect drift across Databricks runtime versions | Pin minimum DBR version in `databricks-full` extra; document the supported range here |
| `DeltaTable.forName` requires the table to exist | Pre-create with `.limit(0).saveAsTable(TARGET)` (shown above); guarded by `tableExists` check |
| `databricks-connect` package versioning is finicky | `pyproject.toml` already has python-version-gated pins; do not add unconditional `databricks-connect` to base deps |
| MLflow run gets orphaned on crash | Use `with mlflow.start_run() as run:` or explicit try/finally with `mlflow.end_run()` |
| Unity Catalog schema doesn't exist on first run | Run `CREATE SCHEMA IF NOT EXISTS` for each layer before any Bronze write |
| UC permissions for the build identity | Document required grants (`CREATE TABLE` on each schema, `READ` on raw source paths) in `10-operations.md` |
