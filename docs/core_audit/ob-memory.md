# ob-memory — audit

## Purpose
`core/onboarding/memory/` owns accepted-decision reuse for the KPI/data-engineering control plane. It persists human answers from blocker panels as reusable, workspace-level business definitions and re-applies them automatically to every matching KPI feature. Sub-responsibilities:

- `workspace_definitions.py` — the durable store + reuse engine. Saves panel answers to `interns/.../contracts/workspace_feature_definitions.json`, mirrors them into `requirements.json`, and applies definitions to `kpi_feature_mapping.json` (scoped/broad/exception logic). Also owns mapping status recomputation.
- `user_decisions.py` — per-KPI (non-reusable) decision store; writes one feature's decision into the mapping + `requirements.json`.
- `wiki_memory.py` — cross-workspace governed reuse cards (`state/team_memory/wiki_memory_index.json`) derived from registries/contracts/sessions.
- `health.py` — confidence-scored read-only health report over workspace + team memory JSON.

Confirmed reuse correctness: `KPIFeatureResolver.resolve()` (`feature_resolver.py:183-185`) loads `load_workspace_definitions` and calls `apply_workspace_definitions_to_mapping` on EVERY resolve, so saved definitions are genuinely re-applied to all matching KPIs. The panel-answer path (`blocker_workflow.py:286-349`) routes all option types into `apply_workspace_definition`. Integration is real, not aspirational.

## Findings

| [BUG] | workspace_definitions.py:212-221 (`load_workspace_definitions`) | On `json.JSONDecodeError` the corrupt store is silently replaced with an empty `definitions: []` skeleton. The very next `apply_workspace_definition` call writes that skeleton back (line 104), so a single transient/partial write **permanently discards every previously-saved human workspace definition** with no error, no backup, no finding. This is the durability hole the sibling audit warned about — and here it drops *reusable* human decisions, the most expensive ones. | On decode failure, do not silently reset: raise (fail loud) or rename the bad file to `*.corrupt-<ts>` before starting fresh; emit a critical finding. Never overwrite a non-empty store after a parse failure. |
| [BUG] | user_decisions.py:116-119 & 433-436; workspace_definitions.py:432-436 | `requirements.json` reads use `except json.JSONDecodeError: requirements = {}`, then `write_text` (lines 130 / 448 / 130). A corrupt requirements file silently loses all prior `user_confirmed_feature_decisions` and `workspace_feature_definitions` audit rows on the next decision. Same silent-drop pattern as above on the audit mirror. | Same as above: back up/rename the corrupt file and surface a finding instead of zeroing it. At minimum log the decode error. |

| [BUG] | workspace_definitions.py:293-298 (`apply_workspace_definition_to_mapping`) | A broad (no `applies_to_kpis`) re-application skips any feature already in a READY state other than `user_confirmed`. ## Cross-package coupling
- `core/storage/workspace_layout.WorkspaceLayout` — every module derives paths (`memory_dir`, `contracts_dir`, `requirements_dir`, `reports_dir`, `evidence_dir`) from it; also `is_dataset_allowed` used by source-column resolution. Tight, correct coupling.
- `core/onboarding/features/blockers` — `workspace_definitions.py` imports `infer_join_candidates`, `normalize`, `prioritize_blockers`. `normalize` is the canonical feature-name matcher used for reuse matching; correctness of reuse depends on it.
- `core/onboarding/kpi/feature_resolver.py` — the real integration point: re-exports `apply_user_decision`/`apply_workspace_definition` for CLI, and (critically) calls `apply_workspace_definitions_to_mapping` on every `resolve()` (line 185). This is what makes definition reuse automatic and workspace-wide.
- `core/onboarding/kpi/blocker_workflow.py` & `blocker_cli.py` — panel answers (`apply-kpi-panel-answer`) flow through `blocker_workflow.apply_kpi_panel_answer` -> `apply_workspace_definition`, passing `applies_to_kpis` from the panel. Confirms CLAUDE.md's "save as workspace-level definition and reuse for every KPI" is implemented.
- `core/onboarding/kpi/cli_agent_confirm_cli.py` — independently calls `load_workspace_definitions` + `apply_workspace_definitions_to_mapping` for the two-step CLI-agent confirm flow.
- `pyproject.toml:83-84` — `prepare-wiki-memory` and `validate-memory-health` are real console entry points; `dashboard.py:4217` runs `validate-memory-health`. Neither wiki_memory nor health is dead.

## Verdict
Functionally the reuse contract is correctly implemented and genuinely wired: human panel answers are saved as workspace-level definitions and automatically re-applied to all matching KPIs on every resolve, with sensible broad-vs-scoped-vs-exception ordering and a non-feature-token guard. That core is production-shaped.

It is **not yet production-ready** because of durability, not logic. The decision store and its requirements/audit mirrors all use the silent `except json.JSONDecodeError: -> {}/empty` pattern (load_workspace_definitions, both `append_*_requirement`s) combined with non-atomic `write_text`. A single interrupted or partial write can silently and permanently erase every saved human decision on the next call — the exact "broad except that discards human decisions" risk flagged in the brief, here landing on the most valuable (reusable, human-confirmed) records. Secondary issues: `_stronger_state` can downgrade confirmed human states during merge/dedup, and wiki_memory does not promote accepted definitions into the cross-workspace index. Recommended before prod: fail-loud-or-backup on corrupt stores, atomic writes, fix `_stronger_state` precedence, and feed workspace_feature_definitions into wiki_memory.
