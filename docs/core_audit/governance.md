# governance — audit

## Purpose
Governance layer of the control plane: defines policy contracts (execution/downcast/failure/approval/SLA), semantic guardrails derived from KPI registries/data models, mode planning, and the promotion gatekeeper (`GovernanceEvaluator`) that turns run evidence into approve/review/reject decisions. It also hosts the enforced safety guards — PHI/PCI remote-upload gate, prompt-injection neutralizer, user-authored data policy, and human-vs-agent decision provenance.

## Findings
| Tag | Location (file:line) | Description | Suggested fix |
| --- | --- | --- | --- |
| [BUG] | op_signals.py:132 | `stuck = ... and question_count == 0` uses the RAW payload value, not `_as_int(question_count)`. If a command returns `question_count` as a string ("0") or omits it (None), `== 0` is False and `stuck` never fires even with `blocked and unresolved==0`. Other branches in the same function correctly normalize via `_as_int`. | Normalize first: `qc = _as_int(question_count) if question_count is not None else None`; gate on `qc == 0`. |
| [BUG] | semantic_contract.py:130-146 | `_extract_kpi_formulas` treats any line containing `|` as a markdown table row and skips header/separator only by name heuristics. A registry markdown line like a prose sentence with a pipe, or a 2-col row whose 2nd cell is empty, can register a bogus KPI rule, and the `:---` separator guard only checks `name.startswith(":---")` (right-aligned `---:` separators slip through). | Detect the separator row by regex on all cells (`^:?-{3,}:?$`); require the formula cell non-empty after stripping. |
| [NOT-PROD] | phi_gate.py:475-481 | `main()` swallows ALL config-load errors with bare `except Exception: cfg = None`, then treats `cfg is None` as "not covered" (fail-safe for blocking, but hides a real misconfiguration from the operator running the CLI). | Catch narrowly and print a redacted warning (`config load failed: <type>`), still defaulting covered=False. |
| [NOT-PROD] | semantic_contract.py:63,180 | `merge_methodology_json` calls `json.loads(path.read_text(...))` with no try/except — a malformed methodology JSON raises and aborts contract build (vs `data_policy`/`phi_gate` which return error-bearing objects). `_read_registry_text` swallows Excel errors broadly (`except Exception`) which can mask a genuinely corrupt registry. | Wrap methodology load in try/except returning a parse-error rule/source note; narrow the Excel except to `Exception` only around the read, log the reason. |
| [INTEGRATION] | injection_guard.py:93 | `scan_text` is exported, documented as the report/panel-facing detector, and unit-tested, but no production caller uses it — only `neutralize_text`/`neutralize_rows` are wired in (document_loader, blocker_question_panel). The "findings for reports and panels" surface is never populated, so injection attempts are silently neutralized but never reported/alerted. | Either wire `scan_text` into panel/report generation to surface findings, or drop the claim that findings reach reports. |
| [INTEGRATION] | phi_gate.py:201,344,388 | `detect_pci_columns`, `enforce_remote_pci_gate`, `assess_workspace_pci` are reached only via `enforce_remote_sensitive_gate` (the documented single entry). Direct PCI functions are public + tested but otherwise unused — acceptable, but confirms `enforce_remote_sensitive_gate` is the only gate callers should use; phi/pci singletons risk being called directly and bypassing the combined order. | Document/mark the per-category gates as internal, or have callers (execution/backend, deployer) always use `enforce_remote_sensitive_gate`. (They do today.) |
| [MISSING] | phi_gate.py:167-188 | `_iter_profile_columns` reads dataset schema purely from `profile_index.json`. There is no guard that the profile is current/non-stale relative to the actual data files — a stale profile that predates a new PHI column would let identifiable data through the gate. | Cross-check profile freshness (source hash/mtime) before trusting it for a PHI block; on staleness fail closed or force re-profile. |
| [MISSING] | injection_guard.py:37-71 | Patterns are ASCII/English-only and anchored to common phrasings. Unicode homoglyph / zero-width / base64 / non-English injection is not covered; comment acknowledges conservatism but there is no length cap or normalization (NFKC) pre-pass. | Add NFKC normalization + strip zero-width chars before matching; document residual gaps. Not a blocker but scope it. |
| [DEAD] | — | No fully dead public symbols found. `scan_text` (see INTEGRATION) is the closest; everything else is imported/called or is a registered CLI entrypoint (`assess-workspace-phi = core.governance.phi_gate:main`). | n/a |

## Cross-package coupling
- Imports from core: `core.failures` (StructuredFailure/`remote_denied`), `core.governance.data_policy` (lazy, inside phi_gate), `core.storage.workspace_layout` + `core.config` (lazy, in CLI `main`), `tools.skill_excerpt` (lazy, advisory in op_signals).
- Imported by: `core.orchestration.loop` (policy/evaluator/mode/contract — the hot path), `core.profiling.data_model_profiler` (DowncastPolicy), `core.optimization.planner` (SemanticContract), `core.execution.backend` + `core.onboarding.databricks.workspace_deployer` + `core.medallion.deploy_plan` (phi_gate sensitive gate + provenance), `core.onboarding.*` (injection_guard, data_policy, provenance, op_signals), `core.dashboard.*` (data_policy).
- Coupling is healthy: contracts/evaluator/semantic/mode form a clean internal cluster; the safety guards (phi_gate/injection_guard/data_policy/provenance) are leaf modules with lazy back-edges, keeping import cost low when disabled. `op_signals` reaching into `tools.skill_excerpt` is the one cross-layer (core->tools) edge, but it is lazy and advisory-only.

## Verdict
Production-ready and unusually well-considered for a safety layer (fail-closed PHI/PCI gate, agent-vs-human provenance, conservative injection neutralizer). Top risk: the PHI gate trusts `profile_index.json` with no staleness check (MISSING) — a stale profile could let identifiable data reach a non-covered target. Secondary: `scan_text` injection findings are never surfaced to reports/alerts despite being the documented detection surface.
