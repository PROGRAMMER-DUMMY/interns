# Tests Architecture Context: `tests`

This document provides an exhaustive reference for the test suite in [`tests`](file:///C:/Users/shubh/OneDrive/Desktop/interns/tests).

## Executive Overview & Architectural Model

The `tests` directory contains pytest unit, integration, and benchmark suites covering core orchestration, execution backends, governance contracts, profiling algorithms, blocker panel flows, and dbt generators.

## Key Test Modules

- [`test_workspace_flow.py`](file:///C:/Users/shubh/OneDrive/Desktop/interns/tests/test_workspace_flow.py): End-to-end integration tests for workspace intent execution and lifecycle stages.
- [`test_kpi_execution_harness.py`](file:///C:/Users/shubh/OneDrive/Desktop/interns/tests/test_kpi_execution_harness.py): Validates SQL execution accuracy against local DuckDB and Databricks.
- [`test_blocker_panel_renderer_previews.py`](file:///C:/Users/shubh/OneDrive/Desktop/interns/tests/test_blocker_panel_renderer_previews.py): Verifies panel rendering and SQL preview generation.
- [`test_phi_gate.py`](file:///C:/Users/shubh/OneDrive/Desktop/interns/tests/test_phi_gate.py): Tests PHI/PII detection and redaction rules.
- [`test_dbt_project_generator.py`](file:///C:/Users/shubh/OneDrive/Desktop/interns/tests/test_dbt_project_generator.py): Validates generation of dbt models, sources, and profiles.
- [`test_dbt_generator_hardening.py`](file:///C:/Users/shubh/OneDrive/Desktop/interns/tests/test_dbt_generator_hardening.py): Emitted-code invariants on the generated dbt project text (`EmittedProjectInvariantTests` et al.) -- liquid clustering, incremental merge safety, WAP publish swap, `dbt parse` gate, `profiles.yml` dev/prod targets on separate catalogs plus `dbt_project.yml`'s `require-dbt-version`, and `CatalogBaseResolutionTests` — `resolve_catalog_and_base` prefers `provision_plan.json`'s concrete catalog, treats an explicit `--catalog` as its own base, and leaves an unprovisioned workspace's declared value unchanged (F21). `test_nothing_inside_the_project_hardcodes_one_targets_catalog` pins that `sources.yml` and the `publish_gold` macro follow `{{ target.database }}` rather than any single catalog literal. `test_failing_tests_persist_the_rows_that_failed` pins the `data_tests:` store-failures block (`as: table`, not dbt's default view, which re-evaluates its predicate after the data has moved). `RelationshipDerivedQualityTests` covers DQ-R2 reaching emitted YAML — an approved relationship contract generates a `relationships` test on the fact key and `unique` on the dimension key, both at `severity: error`; its fixture's KPI cuts by a DIMENSION column on purpose, because a KPI that never touches the dimension never stages it and there would be no `ref()` target. `UnprovenRelationshipTests` pins the stronger guarantee behind that: revoking `allowed_in_sql_generation` does not merely drop the test, it refuses generation outright, which is why the deriver carries no safety check of its own.
- [`test_platform_readiness.py`](file:///C:/Users/shubh/OneDrive/Desktop/interns/tests/test_platform_readiness.py): Unit tests for platform readiness diagnostic tool.
- [`test_provision_apply.py`](file:///C:/Users/shubh/OneDrive/Desktop/interns/tests/test_provision_apply.py): Confirmation refusal, kill switch, idempotent skips, structured failures. Includes `ExternalLocationOverlapTests` (URL-prefix vs name identity, F14) and `CatalogStorageRootTests` (`MANAGED LOCATION` reaches catalog creation and is recorded in the plan, F15).
- [`test_ingestion_run.py`](file:///C:/Users/shubh/OneDrive/Desktop/interns/tests/test_ingestion_run.py): `run-ingestion`'s refusal ladder, statement splitting, stop-on-first-failure, and safe re-runs. `LandedRowVerificationTests` covers zero-row detection with a `CountingRunner` that answers `COUNT(*)` like the warehouse does: a non-empty source landing 0 rows fails, an empty source landing 0 rows does NOT (flagging correct-zero trains operators to ignore the check), and a runner that cannot report counts gets no verdict fabricated for it. `SdkSeamTests` pins the one path every other test mocks away — the SDK client's real name and constructor (F19).
- [`test_dbt_state_publish.py`](file:///C:/Users/shubh/OneDrive/Desktop/interns/tests/test_dbt_state_publish.py): `core.orchestration.dbt_state.publish_state`/`state_download_command` — two `databricks fs cp` calls per `target/` artifact (timestamped + `latest`), no call at all when `target/` is missing, stop-at-first-failure, redacted stderr tail, injectable recording runner (never touches the network).
- [`test_onboarding_databricks_source.py`](file:///C:/Users/shubh/OneDrive/Desktop/interns/tests/test_onboarding_databricks_source.py): Generic UC table discovery and profiling from `workspace_settings.databricks_source` — no workspace/catalog/table name is ever hardcoded in `core/`. Also pins that a PROVISIONED workspace profiles the landed `<provisioned_catalog>.<bronze_schema>` rather than the declared intake pair, and that a discovery failure survives in `_databricks_discovery_error` instead of reading as "zero tables" (F25).
- [`test_intake_discovery.py`](file:///C:/Users/shubh/OneDrive/Desktop/interns/tests/test_intake_discovery.py): Source scanning and path grouping. `EntityGroupingTests` pins both halves of the grouping contract — a folder of distinct entities splits into one table per file and each keeps its REAL path including the extension (F22), while a genuine part-file layout stays one table pointing at the directory.
- [`test_ingestion_generator.py`](file:///C:/Users/shubh/OneDrive/Desktop/interns/tests/test_ingestion_generator.py): Emitted ingestion code — Auto Loader vs `COPY INTO` selection, checkpoint placement, manifest shape, that CSV declares `'header' = 'true'` while self-describing formats do not (F23), and that both paths set a rescued-data column — `addNewColumns` covers an added column but not a changed TYPE, which otherwise nulls silently.
- [`test_databricks_client_read_path.py`](file:///C:/Users/shubh/OneDrive/Desktop/interns/tests/test_databricks_client_read_path.py): `DatabricksClient.execute_query` against a faked `statement_execution` seam (real `StatementState` enum, no network). `ResultPaginationTests` pins that every chunk is read via `next_chunk_index`, and that passing `max_rows` RAISES rather than returning a prefix — a truncating cap would reintroduce the silent-wrong-answer bug it guards (P1). `PollCeilingTests` pins the deadline and the bounded retry: a hung statement raises `TimeoutError` instead of pinning a caller, and one transient `get_statement` blip no longer abandons a statement that is running fine server-side (P2).
- [`test_idempotency.py`](file:///C:/Users/shubh/OneDrive/Desktop/interns/tests/test_idempotency.py): op-id derivation and the applied-op log. `FailedRunIsNotAnAppliedOpTests` drives the real `run_workspace_command` envelope: a payload reporting `ok: False` writes no applied-op row, a successful one still does (F24). `OpIdCoversConsumedArtifactTests` pins that a changed `provision_plan.json` yields a new `op_id` while an unchanged one still replays, AND — by reading the shipped CLI source — that `apply-provisioning`/`run-ingestion` actually pass the fingerprint, since a green hash function proves nothing about the command (F16).
- [`test_cosmos_dag.py`](file:///C:/Users/shubh/OneDrive/Desktop/interns/tests/test_cosmos_dag.py): Cosmos wiring for the `dbt_build` stage, exercised without Airflow/Cosmos installed — the remote-execution gate, empty-workspace refusal, `_read_profile_name`, ghost-reconcile qualification (F20) and its concrete-catalog resolution (F21), and `DbtTargetMatchesProvisionedEnvTests`: the dbt target comes from `provision_plan.json`'s `env`, never the literal `"prod"`, which pointed the DAG at an unprovisioned catalog (F26). That last one asserts on `build_dbt_tasks`'s SOURCE, because the operator cannot be constructed here.
- [`test_deploy_gates.py`](file:///C:/Users/shubh/OneDrive/Desktop/interns/tests/test_deploy_gates.py): The five deployment gates on synthetic fixtures, plus the fail-closed contract — an unlistable medallion runs directory (G1) and a non-numeric panel `open_count` (G2) must return a blocking `GateVerdict`, never raise, because a gate that raises has blocked nothing.
- [`test_salt_store.py`](file:///C:/Users/shubh/OneDrive/Desktop/interns/tests/test_salt_store.py): `materialize_salt_if_missing`'s write path against a fake home directory — a corrupt `secrets.toml` is refused with the other workspace's bytes intact, and a readable one is extended rather than replaced. Never touches the real home or Databricks.
- [`test_airflow_health.py`](file:///C:/Users/shubh/OneDrive/Desktop/interns/tests/test_airflow_health.py): `core.orchestration.airflow_health.check_airflow_health` against a fake, injectable `http` — paused DAG makes `ok: False`, healthy scheduler + unpaused DAG makes `ok: True`, unhealthy scheduler makes `ok: False` even when unpaused, a connection error reports `scheduler: "unreachable"` (never raises), a per-DAG lookup failure after a reachable scheduler folds into `paused_dags` rather than reading as healthy, and the JWT never appears anywhere but the `Authorization` header/is redacted out of any surfaced error text. `test_orchestration_hardening.py`'s `BackfillPoolTests` (same file's static-source-inspection style as `DbtStateWiringOrderTests`, since Airflow isn't installed here) pins that `airflow_dag.build_dag()` wires the backfill task with `pool="backfill"`, documents the one-time `setup_pools` bootstrap (`airflow pools set backfill 2 "bounded replay capacity"`) in the module header, and declares the `allow_full_refresh` param — a templated-but-undeclared Airflow param raises at render time, so the guard below would break the task rather than gate it. `BackfillSeamTests` pins that guard: with no model declaring `event_time`, `backfill_command` REFUSES (`exit 1` positioned before `run-dbt-backfill`, asserted by index — a refusal after the command it refuses has refused nothing) and names both exits, declare `event_time` or pass `allow_full_refresh`.
